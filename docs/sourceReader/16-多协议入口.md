# 16 多协议入口：同一网关的多套协议外观

> 基准提交：`1a64da55`（本地 `adrian`）；核对日期：2026-11-17。范围：网关对外暴露的多套协议入口（OpenAI 兼容、Anthropic 兼容、Ollama 兼容）、协议间模型名映射、`/v1` 前缀规范化。不覆盖：Provider 把内部消息翻译为具体上游协议（见 [11 Provider 与流式](11-函数级走读-Provider与流式.md)）、单条请求的选路与回退（见 [10 路由限流与回退](10-函数级走读-路由限流与回退.md)）。

## 需求视角

### 1 使用场景、目标与结果

不同客户端说不同的「方言」：OpenAI SDK、Claude 系客户端（Claude Desktop 第三方网关、Claude Code、Anthropic SDK）、Ollama 本地工具都按各自协议发请求。目标是让**同一个网关、同一批 key** 能被这些异构客户端直接使用——用户不必为换客户端而换网关。完成后：把任意兼容客户端的 base url 指向本网关，即可用同一份上游 key 池对话。

### 2 参与者与业务前置条件

| 参与者 | 角色 | 前置条件 |
|---|---|---|
| OpenAI 兼容客户端 | 触发者 | base url 指向网关 `/v1` |
| Anthropic 兼容客户端 | 触发者 | base url 指向网关，按 Anthropic 协议发 `/v1/messages` |
| Ollama 兼容客户端 | 触发者 | base url 指向网关的 Ollama 入口 |
| 协议入口路由 | 承接者 | 已挂载对应 router、鉴权通过 |
| 模型映射层 | 加工者 | Claude 家族映射配置可用 |

前置条件不满足时：协议不支持（如 Ollama 仿真关闭）、模型名无法映射到上游、鉴权失败，均会在入口处被拒或降级，不进入选路。

### 3 业务调用层次

客户端 → 协议入口路由（OpenAI/Anthropic/Ollama 之一）→ 协议归一化（把该协议请求翻译成内部统一形态、模型名映射）→ 交由统一的选路与回退（见 10）→ Provider 出站（见 11）。各协议入口是并列的「门面」，共享同一套后端能力。

### 4 业务数据流转

| 阶段 | 触发者 / 接收者 | 输入资料 | 业务处理 | 输出结果 | 条件不满足时 |
|---|---|---|---|---|---|
| 1 进入口 | 客户端 → 协议路由 | 该协议原生请求体 | 鉴权、`/v1` 前缀规范化 | 归一化前的原始请求 | 前缀错误会 404，故先规范化 |
| 2 归一化 | 协议路由 → 映射层 | 模型名、消息、参数 | Anthropic thinking→effort、模型名映射 | 内部统一请求 | 模型名无法映射则报错/降级 |
| 3 交付后端 | 映射层 → 选路 | 统一请求 | 走选路与回退 | 上游响应 | 见 10 |
| 4 回译 | Provider → 协议路由 | 上游响应 | 按客户端协议回译（含流式帧） | 该协议原生响应 | — |

### 5 主流程、业务分支与异常结果

- **OpenAI 兼容**：base url 以 `/v1` 结尾，客户端自己再拼 `/v1/models`、`/v1/messages`。
- **Anthropic 兼容**：把 Anthropic 客户端的 thinking 参数映射为内部 effort（`effortFromAnthropicThinking`）；Claude 家族模型名按映射表解析到实际上游模型（`resolveAnthropicModel`）。
- **`/v1/v1` 双前缀**：当 OpenAI 风格 base url（以 `/v1` 结尾）被粘进 Anthropic 客户端时，每次调用都会落到 `/v1/v1/...` 而 404。由于没有任何路由合法地挂在 `/v1/v1` 下，把重复前缀折叠成单个是**无歧义**的修复。
- **Ollama 兼容**：有三种仿真模式（关闭 / 仅 loopback 开放 / 需要 key），并只在符合本机条件时开放。

### 6 边界、非目标与验收表现

- 多协议入口只做「协议外观」的进出翻译；上游协议适配在 Provider 层（11）。
- 本篇为静态走读，**未启动服务、未发任何请求**；折叠/映射的运行表现 `[待运行验证]`。

## 技术视角

### 7 实现地图：入口、注册点、核心源码与测试

- **挂载点**：`server/src/app.ts:203` `app.use(collapseDoubledV1Prefix)`（在路由前统一规范化）。
- **`/v1` 折叠**：`server/src/middleware/doubled-v1.ts` · `collapseDoubledV1Prefix+0`（20）、正则 `DOUBLED_V1`（6）。测试 `server/src/__tests__/routes/doubled-v1-prefix.test.ts`。
- **Anthropic 入口**：`server/src/routes/anthropic.ts` · `anthropicRouter+0`（51）、`handleMessages+0`（492）、`extractAnthropicCompat+0`（183）、`effortFromAnthropicThinking+0`（130）。
- **Anthropic 模型映射**：`server/src/services/anthropic-map.ts` · `resolveAnthropicModel+0`（131）、`classifyClaudeFamily+0`（82）、`getClaudeModelMap+0`（51）、`setClaudeModelMap+0`（67）、`CLAUDE_FAMILIES+0`（17）、`TIER_SELECTORS+0`（34）。
- **Ollama 入口**：`server/src/routes/ollama.ts` · `ollamaRouter+0`（16）、`getOllamaEmulationMode+0`（20）、`isLoopback+0`（26）、`normalizeOllamaModel+0`（53）。
- **OpenAI 兼容出站**：`server/src/providers/openai-compat.ts`（属 Provider 侧，见 11）。

### 8 技术前置条件

- 各 router 在 `app.ts` 装配时挂载；`collapseDoubledV1Prefix` 必须早于具体路由。
- Anthropic 映射依赖 Claude 家族映射配置（`getClaudeModelMap` 读、`setClaudeModelMap` 写）。
- Ollama 仿真模式存于 settings（`ollama_emulation`），值域 `off`/`open-loopback`/`key-required`。

### 9 真实调用层次与关键源码定位

请求进入 → `app.ts` 中间件链 `collapseDoubledV1Prefix`（203）先折叠重复 `/v1` → 命中对应 router：
- Anthropic：`anthropicRouter` → `handleMessages` → `extractAnthropicCompat`（抽取兼容参数）+ `effortFromAnthropicThinking`（thinking→effort）→ 模型名经 `resolveAnthropicModel` 映射。
- Ollama：`ollamaRouter` → 鉴权（`isLoopback` + 仿真模式）→ `normalizeOllamaModel` 归一模型名。
两者最终都汇入统一选路（10）与 Provider 出站（11）。

### 10 技术数据流程

- `/v1` 前缀：`req.url` 以 `/v1/v1` 开头时按 `DOUBLED_V1` 折叠为单个 `/v1`，锚定整段（`/v1/v1beta`、`/v1/v1x` 不受影响）。
- Anthropic thinking：`effortFromAnthropicThinking` 把 Anthropic 的 thinking 配置转换为内部 effort 取值。
- Claude 模型名：`resolveAnthropicModel` 经 `classifyClaudeFamily`/`resolveListedClaudeAlias` 解析为上游模型或 tier 选择器（`tier:pro`/`tier:mid`/`tier:normal`）。
- Ollama 模型名：`normalizeOllamaModel` 归一为内部模型标识。

### 11 核心机制、分支、失败处理与不变量

**不变量**：没有任何合法路由挂在 `/v1/v1` 下，故折叠该前缀不会误伤正常请求；各协议入口共享同一套选路/回退与 key 池。

- 折叠只在 `req.url.startsWith('/v1/v1')` 时触发，正则锚定整段，避免把 `/v1/v1beta` 误折。
- Ollama 开放度由仿真模式决定：`off` 完全关、`open-loopback` 仅本机、`key-required` 需 key；本机判定委托 `lib/loopback.ts`（见 [05 API 与接口设计](05-API与接口设计.md)）。
- Anthropic 模型映射找不到目标时按映射层定义的分支报错或降级，不进入选路。
