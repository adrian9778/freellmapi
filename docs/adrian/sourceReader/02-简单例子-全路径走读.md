# 02 简单例子 —— 全路径走读

> 本篇为**第二层**：选一个真实、最小、可运行的成功场景（`POST /v1/chat/completions`），从入口追踪到结果。只走主成功路径，脱敏输入输出，真实文件/函数/参数/返回值。

---

## 0 场景定义

**请求**：用户用 OpenAI SDK 向本地 gateway 发送一次普通聊天完成请求。

```bash
curl -X POST http://127.0.0.1:3001/v1/chat/completions \
  -H "Authorization: Bearer freellmapi-abc123..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

**预期结果**：SSE 流式返回 `data: {"id":"chatcmpl-...","choices":[{"delta":{"content":"Hi there!"}}]}`，最终 `data: [DONE]`。

**环境假设**：
- Server 已启动，DB 已初始化，至少有一个 provider (如 Google Gemini) 配置了有效 key 且处于 `healthy` 状态
- Fallback 链里该模型优先级最高，且未触及任何限流
- Desktop 模式端口为 31415，但逻辑完全一致

```typescript
// proxy.ts:66-73
function requireInferenceAuth(req: Request, res: Response): ResolvedAuth | null {
  const auth = resolveAuth(extractApiToken(req));  // lib/system-prompt.ts:resolveAuth
  if (!auth) {
    res.status(401).json({ error: { message: 'Invalid API key', type: 'authentication_error' } });
    return null;
  }
  return auth;
}
```

- `extractApiToken()`（proxy.ts:78-89）支持三种头：`Authorization: Bearer`、`x-api-key` (Anthropic)、`x-goog-api-key` (Gemini)

- **统一 key 格式**：`freellmapi-` + 48 hex chars（`db/index.ts:233` `regenerateUnifiedKey()`）

### 2.2 请求体规范化（proxy.ts 主处理器内）

关键步骤（按执行顺序）：

1. **模型 ID 解析**：`const requestedModel = req.body.model ?? 'auto'`；`isAutoModel()` (proxy.ts:50-54) 判断是否为自动路由

8. **上下文移交**：`maybeInjectContextHandoff()` (services/context-handoff.ts) → 如果有前序模型输出，注入到 messages

## 3 路由器核心：`router.ts:pickModel()` + `streamChatCompletion()`

### 3.1 构建路由链：`routeRequest()` (router.ts 约 500 行)

```typescript

  req: ChatRequest,
  opts: RouteOptions

  // 1. 从 model-state.ts 获取候选模型（按 fallback_config.priority 排序）
  const chain = await resolveRoutingChain(db, req, opts);
  // 2. 对每个候选：checkAndReserve() 限流预检
  // 3. 选第一个通过的，返回 RouteResult

```

**`resolveRoutingChain()`** (router.ts:650+) 做的事：
- 从 `fallback_config` 表 + `profiles` 表 + `custom_endpoint` 表构建完整候选链
- 过滤：`enabled=1`、有健康 key、`status !== 'error'`、context window 足够、vision/tools 能力匹配
- 计算 bandit 分数：`scoring.ts:combineScore()` → `reliabilityPosterior()` + `speedScore()` + `intelligenceComposite()` + `headroomFactor()` + `rateLimitFactor()` + 动态惩罚 `getPenalty()`
- 排序：`match_tier` (0 优先) → 分数降序 → priority 升序

### 3.2 限流预检：`ratelimit.ts:checkAndReserve()` (ratelimit.ts 约 200 行)

```typescript
// ratelimit.ts:200+
export function checkAndReserve(
  keyId: number,
  platform: string,
  modelId: string,
  estimatedInputTokens: number,
  estimatedOutputTokens: number,
  endpointScope: string
): { ok: boolean; reason?: string; retryAfterMs?: number } {
  // 1. RPM: 内存 Map<keyId+modelId, count> + SQLite rate_limit_usage 持久化
  // 2. RPD: 同理，日维度
  // 3. TPM/TPD: token 级别，按 estimatedTokens 预留
  // 4. Provider 级总配额：provider_quota_state 表
  // 5. Key 并发租约：acquireLease(keyId) / releaseLease(keyId)

```

**关键常量**（ratelimit.ts:30-50）：
- `RPM_WINDOW_MS = 60_000`、`RPD_WINDOW_MS = 86_400_000` (UTC midnight)
- `TPM_WINDOW_MS = 60_000`、`TPD_WINDOW_MS = 86_400_000`
- `COOLDOWN_BASE_MS = 60_000` (1min)，指数退避最高 `COOLDOWN_MAX_MS = 3_600_000` (1h)
- `KEY_CONCURRENCY_LIMIT = 3` (每 key 同时在途请求数)

### 3.3 选中路由后：`streamChatCompletion()` (router.ts 约 800 行)

```typescript
// router.ts:800+
export async function* streamChatCompletion(
  route: RouteResult,
  req: ChatRequest,
  opts: StreamOptions
): AsyncGenerator<StreamChunk> {
  const { provider, modelId, apiKey, keyId, release } = route;
  
  try {
    // 1. 调用 provider 的流式方法
    for await (const chunk of provider.streamChatCompletion(modelId, messages, apiKey, opts)) {
      // 2. 工具调用救援：rescueInlineToolCalls() 对 chunk 实时处理
      // 3. 记录 token usage：opts.onTokenUsage?.(input, output)
      yield chunk;
    }
    // 4. 成功：recordResult() 计入用量、recordSuccess() 减惩罚、release() 释放租约
  } catch (err) {
    // 5. 失败：recordFailure() 记入冷却、recordRateLimitHit() 加惩罚、release() 释放租约
    // 6. 抛出给 fallback-loop 处理重试
  }
}
```

```typescript
async *streamChatCompletion(modelId, messages, apiKey, opts) {
  const client = new GoogleGenerativeAI(apiKey);  // @google/generative-ai
  const model = client.getGenerativeModel({ model: modelId });
  
  // 转换 messages → Google 格式 (contents + systemInstruction)
  const { contents, systemInstruction } = convertMessages(messages);

    contents,
    systemInstruction,
    generationConfig: { temperature, topP, topK, maxOutputTokens, ... },
    safetySettings: [...],
  }, { signal: opts.signal });
  
  for await (const chunk of stream) {
    // 转换 Google chunk → 统一 StreamChunk

  }
}
```

## 9 失败路径预览（第三层展开）

主成功路径之外，以下分支在第三层详细拆解：

1. **限流预检失败** → `checkAndReserve` 返回 `{ok:false, reason:'rpm'}` → router 尝试下一候选
2. **上游 429/5xx** → `recordFailure` + `recordRateLimitHit` → `fallback-loop.ts:runFallbackLoop` 重试下一模型（最多 20 次 / 60s 墙钟预算）
3. **工具调用格式错误** → `tool-validate.ts:invalidToolCallReasons` → 自动修复或返回错误
4. **Context window 溢出** → `applyTokenBudget` 截断 messages / 跳过该模型
5. **所有模型耗尽** → `RouteError` with `diagnostics[]` → `summarizeExhaustion()` 生成客户端可读错误
6. **客户端中断** → `isClientAbortError` → 不计入失败、不触发冷却、释放租约
